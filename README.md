# QLark 云雀

基于 [NapCat](https://github.com/NapNeko/NapCatQQ) 的 QQ 聊天机器人 **Windows 桌面客户端**：
双击打开、扫码登录、在图形界面里配置，不用改配置文件也不用碰命令行。

适配任何 **OpenAI API 兼容**的服务（DeepSeek / MiMo / OpenAI / 自建中转都行），
主打 **多人设对话** 与 **长期记忆**，群聊和私聊都能用。

- 版本：**v2.2** ｜ Python 3.13 ｜ 界面 pywebview（Edge WebView2）｜ 协议 OneBot 11

> [!WARNING]
> **仅供学习交流。** 请遵守腾讯 QQ 用户协议与当地法律法规。
> 使用非官方客户端存在被风控甚至封号的风险，**请自行评估、自担后果**。

## 特性

| | |
|---|---|
| **多人设** | 一份人设一套性格、口癖、提示词；不同群挂不同人设，记忆互不串味 |
| **长期记忆** | 按 `<会话>:<人设>` 独立存储，未压缩满 N 轮自动压成摘要；面板能看到「未压缩 X / 满 N 轮」 |
| **模型自主决定回复形态** | 回多长、分不分段、配不配表情、发不发语音，全都由模型看情境判断，**没有骰子** |
| **免 @ 接话** | @ 一次之后一段时间内不用再 @，而且不会因为对方连发碎片就回一串「嗯」 |
| **能听能说** | 引用消息里的文字、图片、视频、聊天记录都读得到；短句可以发成语音 |
| **看图 / 看视频** | 图片交给视觉模型，视频把直链交给模型原生解码（不下载不抽帧）；**上下文里只保留最近一段视频** |
| **能查实时数据** | 可选接和风天气：问天气时自动查真实数据再回；**默认关闭**，开了才会把城市名发给第三方 |
| **风控** | 限流、敏感词、白名单、@ 触发，尽量别把号玩坏 |
| **全图形界面** | 登录、配置、人设、记忆、日志都在一个窗口里，暗色 / 亮色主题 |

## 核心设计：为什么没有骰子

v1 用随机数决定「这一轮要不要分段」「要不要配表情」「回多长」。
这个做法有个根本问题：**上下文盲** —— 在生成之前就把形态定死了，根本不知道对方正在说什么。

v2 把这套骰子**全部删掉**，改成让模型自己判断：

| 以前（代码掷骰子） | 现在（模型判断） |
|---|---|
| 25% 概率分段 | 想分几条就分几条（有上限） |
| 20% 概率配表情 | 这句好笑就配，不好笑就不配 |
| 25%/35%/10% 长度档位 | 打招呼就两个词，对方在情绪里就认真回 |
| — | 短句可以发成语音 |

代价是失去了固定频率控制，所以提示词里给的是**判断标准**而不是概率，
并且在仪表盘的「回复形态」卡片里显示实际使用率 —— 太高就回去调提示词。

**每一轮**都会注入【输出规则】和末尾的格式提醒，模型只输出一个 JSON 对象：

```json
{"messages": ["第一句", "第二句"], "meme": "开心", "voice": false, "emotion": "开心"}
```

代码只负责**护栏**，不负责删内容：
语音超过字数就改发文字、分段超过上限就合并、表情名不在目录里就忽略、
JSON 解析失败就先让模型重写一次，还不行就把原文抢救出来照发 —— **绝不因为格式问题把回复丢掉**。

## 免 @ 接话：保活 + 合并

群里每说一句都得 @ 一次非常烦人，但"不 @ 也永远回"会让机器人变成每句都插嘴的复读机。
所以做了两层：

### ① @ 激活保活

```
A @ 机器人        → 开一个 60 秒的窗口，回他
A 继续说（不 @）   → 窗口续期，照常回
A 停满 60 秒      → 窗口自动关闭，之后又要 @ 才会理
```

**窗口按 `(会话, 用户)` 独立。** 别人说话既不能给他续期、也不能蹭用他的窗口 ——
否则群里一直有人说话窗口就永远不关，那比"每句都要 @"更糟。

### ② 连发消息合并

有人习惯把一句话拆成好几条发（"在" "吗" "问个事"）。每条都回会变成
「咋了 / 嗯？ / 说」三连。所以窗口内的消息先攒起来：

```
对方：在            ┐
对方：问个事        │  全部进缓冲，计时重置
对方：你有空吗      ┘
── 静默 3 秒 ──
机器人：一次回完这三条
```

- **静默 3 秒**后合并发出；每来一条碎片就重新计时
- **硬上限 15 秒**：从第一条算起，防止对方一直打字导致永远不吭声
- **@ 立刻回**，但会把已攒的碎片一起吸收进来，不会先回一个「嗯？」再回正式答案
- 合并后每个碎片**一行**进记忆，保留"他是一句一句发的"这个信息

> 为什么不用"每 15 秒轮询一次"：那样单条消息的延迟取决于它恰好落在哪个格子里
> （0～15 秒随机），同样的话忽快忽慢，比稳定偏慢更假。

## 语音回复

调用 MiMo 的 `mimo-v2.5-tts-voicedesign`（自定义音色），**共用对话的 Base URL 和 Key**，
只单独配模型名。模型在 JSON 里写 `"voice": true` 时才会走语音。

几条实测得到的约束，都已经写进代码里了：

- **不需要自己转 silk** —— NapCat 发送时会检测并自动调用转换（日志会打「语音文件X需要转换成silk」）
- **必须 ≤ 20 字**：46 个字要念 21 秒，没人愿意听完长语音
- **只能发一条**：多条语音会变成连续轰炸
- **任何一环失败都退回文字**：合成报错、超时、返回空音频、写文件失败，一律改发文字，绝不丢回复

音色描述写在「人设配置 → 音色描述」里。它是决定声音年龄感的关键：

| 写法 | 效果 |
|---|---|
| 小女孩、奶气、轻快 | 稚嫩（约 286 Hz） |
| 少女、清透干净 | 清纯 |
| 慢半拍、慵懒、有笑意 | **会变成成熟御姐**，慎用 |

## 引用消息

别人引用一条消息再说话时，机器人会去把被引用的内容取回来看：

| 类型 | 处理 |
|---|---|
| 文字 | 直接拼进上下文 |
| 图片 | 交给多模态（最多 2 张） |
| 视频 | 直链交给模型原生解码（`video_url`，不下载不抽帧） |
| 语音 / 表情 / 文件 | 渲染成标记，至少知道"那里有个视频" |
| 转发的聊天记录 | 展开成「甲：… / 乙：…」 |

OneBot 的 `reply` 段只带消息 ID 不带内容，所以要额外调一次 `get_msg`。
**取不到就当作没有引用**，绝不卡住回复（对方可能已经把原消息删了）。

## 视频

收到视频（直发或引用）时，QLark **不下载 mp4、不抽帧、不装 ffmpeg** ——
NapCat 给的直链会原样放进请求的 `video_url` 段，服务端自己拉取解码。
实测一段 1MB 的短视频约 1100 video token，所以有三条硬约束：

- **上下文里只保留最近一段**：这一轮发的 / 引用的优先，否则从历史里补最近那条
- **直链约 2 小时过期**（带 `rkey`）：过期的历史视频按 `[视频]` 占位处理，不会再塞进请求
- **超时放宽到 180s**：服务端要先拉完整段视频，默认 60s 必然踩线（`video_timeout_s` 可调）

关掉视频理解：配置里把 `video_understanding` 设为 `false`，一律降级成 `[视频]` 占位。
模型不支持视频（400/422 明确说不支持 `video_url`）时会自动降级成纯文本重试一次。

## 趣味功能（可选）：和风天气

「趣味功能」页里配置，**默认关闭** —— 开着就意味着会把聊天里提到的城市名发给第三方。

每个功能各自一个开关（目前只有天气），没有"总开关"：**打开天气查询才会查，关掉就完全不发请求**。

### 能做什么

聊天里问天气时，机器人会**先查真实数据再回答**，而不是瞎编：

```
你：洛阳天气如何？
它：洛阳现在 15℃ 有雾，今天 12 到 16 度，明天有小雨，出门记得带伞
```

三种情况都会触发：

- 命中**可编辑的触发词表**（默认 26 个：天气 / 气温 / 下雨 / 带伞 / 好热 …）
- **接着刚才的天气话题**只发一个短问句（"洛宁呢"、"那明天呢"）
- 或者干脆只发一个地名（"菏泽"）—— 前提是 10 分钟内聊过天气

### 触发词是可编辑的数据表

「趣味功能 → 天气」页里就是一张表：每个词一条、点 × 删除、输入框 + 「添加」新增、
「恢复默认」回到内置那 26 个。**保存时整份提交**，改了立刻生效（下一轮消息就按新表判断）。

设计上有意只认"整词命中"，默认不放「热 / 冷 / 雨」这些单字 ——
"热干面"会白触发一次调用。想让它更敏感，自己加词就行；判断"要不要真查"
仍然由模型做，多触发的代价只是一次约 113 token 的小调用。

### 怎么接的（不用 function calling）

这个端点上 `tools` 和 `response_format: json_object` **互斥**（实测：带 json_object 时
模型会把 tool call 写进 content，回复协议直接崩）。所以走的是"意图 JSON"：

```
触发词命中 → 一次极小调用解析出 {"city":"成都"} → 查和风 → 渲染成一句人话
→ 作为【实时天气】放进末尾 system（紧挨用户消息）→ 照常走 JSON 回复协议
```

几个细节：

- **注入位置在末尾**：塞进开头那段 system 时中间隔着几十轮历史，模型经常当没看见
- **同城 10 分钟缓存**：群里连问三次北京只打一次和风
- **"那明天呢"会继承上文城市**，不会跑偏到默认城市
- **查不到时禁止空头承诺**：会让它直说"查不到"，而不是回一句「我查一下，稍等」然后没下文
- 任何一步失败（超时 / 额度 / 城市不存在）都**安静跳过**，回复照常

### 配置

| 字段 | 说明 |
|---|---|
| 启用天气查询 | 该功能的开关；关掉时不发任何外部请求 |
| 触发词 | 可编辑的表格，命中任意一个就去查 |
| API Host | 控制台「设置」里那一行，形如 `xxxxxx.re.qweatherapi.com`；**公共域名 `api.qweather.com` 已失效** |
| API Key | 控制台生成的凭据，只回显打码值；留空表示不修改 |
| 默认城市 | 用户没提城市时用（"今天天气怎么样"） |

「测试连接」会用表单里的值真打一次和风，**不保存**。

## 记忆

- 按 `<会话>:<人设>` 独立存储，群聊里所有人**共用一份**记忆
- **压缩按"未压缩轮数"触发**：一轮 = 一问 + 一答。攒够 W 轮（默认 20）才把最早那批压成摘要，
  摘要永远保留，超预算时先丢最早的原文
- **面板按轮显示**：`54 条原文 · 27 轮 · 未压缩 27 / 30 轮` —— 条数和轮数差一倍，
  只看条数很容易误判成"早就该压了"（v2.2.1 修的就是这个）
- **手动「立即压缩」不受 W 限制**：有一轮完整问答就能压，自动压缩仍然严格按 W 触发
- **图片不存 base64**，只存文件名，图片本体在 `<数据目录>/media/`
- **最近 2 轮的真实图片会放回上下文**，更早的退化成纯文本
- 机器人自己说的话存**模型原始输出的 JSON** —— 这样回看历史时示范也是 JSON，格式自洽

## 快速开始

### 1. 准备 NapCat 运行时

QLark 本身**不带** NapCat。两种方式：

- **用带运行时的发布包**（推荐，开箱即用）
- **自己放**：把 NapCat 目录放到 QLark 的 `runtime/napcat/` 下，或在配置里指定路径

首次启动如果没找到，界面会提示，跟着向导走即可。

### 2. 安装依赖

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 3. 配置模型

双击打开 QLark → 首启向导，或者进「模型配置」页：

| 字段 | 填什么 |
|---|---|
| Base URL | `https://api.deepseek.com/v1` 或你的服务地址 |
| API Key | 对应服务的 Key |
| 模型名 | 例如 `deepseek-chat`、`mimo-v2.6-flash` |
| 视觉模型 | 可选，要让它看图就填 |
| 语音合成模型 | 可选，例如 `mimo-v2.5-tts-voicedesign` |

点「应用」即可，不用重启。

### 4. 运行

```powershell
python run.py
```

或者双击打包好的 `QLark.exe`。

## 常见问题

### 首次登录可能出现的"两次扫码"

NapCat 首次登录会先写一份账号配置，QLark 检测到之后会重启一次 NapCat 让它生效，
所以**可能要扫两次码**。这是正常的，扫完就会进入"已登录"。

### 卡在"已登录，正在初始化…" / 消息发不出去

多数是 OneBot 端口没通。检查：

1. NapCat 是否真的在跑（任务管理器里能看到）
2. 「模型配置 → NapCat 连接」里的端口和 NapCat 配置是否一致
3. 日志页有没有 `连接失败` / `HTTP 401`

### 机器人"在线但完全不回复"

按顺序排查：

1. **群里没 @ 它** —— 群聊默认必须 @（或者用了免 @ 保活）
2. **暂停了** —— 仪表盘上有没有「已暂停」标签
3. **限流** —— 同一会话一分钟内回太多次会被拦，日志里有提示
4. **敏感词** —— 命中的消息会被直接忽略
5. **模型报错** —— 看日志里有没有 `HTTP 4xx` / `余额不足`

### 语音发不出去

先看日志里有没有这几行：

```
语音合成完成（mp3，18.5 KB，语气「开心」）
语音文件X需要转换成silk
转换成功! 时长: 2.616
发送 -> 私聊 (…) [语音 2s]
```

- 只有第一行没有后面的 → NapCat 的 ffmpeg 组件有问题，重装 NapCat 运行时
- 一行都没有 → 模型没选语音，或者语音总开关 / 人设开关没开

### 引用内容取不到

日志里会有 `引用消息取不到内容（id=…）`。可能是原消息被撤回了，
或者 NapCat 版本对 `get_msg` 的返回结构不同。这条不影响回复，只是看不到引用内容。

### 开了趣味功能，问天气还是说"没有实时数据"

按顺序检查：

1. 「趣味功能」页的**总开关**打开了吗（页头标签应显示"已启用"）
2. API Host 是否是**自己账号的专属域名**（`xxx.re.qweatherapi.com`）——
   公共的 `api.qweather.com` / `devapi.qweather.com` 现在一律返回 `Invalid Host`
3. 点「测试连接」，看是超时、凭据无效（401）还是额度用尽（403）
4. 日志里找这几行：`天气已注入：…（xxxms）` 是成功；`天气查询失败（城市）：…` 会写明原因

另外：**天气类消息会多一次极小调用**（约 113 token）去解析城市，所以延迟会比普通回复高 1~2 秒。

  （踩过三次：人设开关、模型配置、回复形态卡片）
- `tests/test_no_secrets.py`：仓库里出现真实凭据就失败（32 位十六进制 / `*.qweatherapi.com` / `sk-…`）

### 打包成 exe

```powershell
python tools\build_exe.py              # 打包到 dist\QLark\
python tools\build_exe.py --no-runtime # 不带 NapCat 运行时，包更小
python tools\build_exe.py --check      # 只做前置检查，不打包
```

产物是**免安装目录**，整个 `dist\QLark\` 拷走就能用。

> [!IMPORTANT]
> **不要把跑过的那份直接分发出去。** QLark 会把 QQ 号、token、登录态写进
> 自己所在的目录 —— 你调试时运行过的那份已经带了你的隐私。
> 发布前用 `--clean-dir` 清一遍（它**只清理并校验，不打包**）：
>
> ```powershell
> python tools\build_exe.py --check
> python tools\build_exe.py
> # 确认 dist\QLark 里没有 onebot11_<QQ号>.json / qrcode.png / cache 之后再压缩
> ```

### 「像不像人」评测

改提示词不能靠"我觉得好点了"：

```powershell
python tools\eval_humanity.py              # 18 个场景各跑 1 次
python tools\eval_humanity.py --runs 3     # 每场景 3 次，减少偶然性
python tools\eval_humanity.py --no-rubric  # 关掉判断表做对照
```

评分是**启发式**的（数关键词、判断有没有追问词），不是让模型自评 ——
那样既贵又不可复现。分数只用来比较「改前 vs 改后」，不追求绝对正确。

## 数据与配置

所有用户数据都在 **`%LOCALAPPDATA%\QLark`**：

| 路径 | 内容 |
|---|---|
| `data\qlark.db` | 配置、人设、记忆、统计（SQLite） |

|---|---|

## 已知限制

- **只支持 Windows**（依赖 Edge WebView2 与 NapCat 的 Windows 运行时）
- 仅适配 OneBot 11 的 HTTP 通信方式，不支持的实现需要改 `onebot/`
- 语音合成目前按 MiMo 的 `voicedesign` 接口实现，换服务要改 `llm/tts.py`
- 群里所有人共用一份记忆，人多了会串味 —— 这是设计取舍，不是 bug
- 趣味功能目前**只有天气**，且依赖和风天气（要自己申请专属 API Host + Key）；
  换别的数据源要写新的 `fun/` 模块
- 天气只按**城市名**查，不会推断"我现在在哪"；"老家""学校"这类说法要靠默认城市兜底

## 数据与隐私

- 所有数据**只存在本机**，QLark 不上传任何东西
- 调用模型时会把对话内容发给你配置的服务商，请自行阅读对方的隐私政策
- **开了趣味功能**，问天气时会把**城市名**发给和风天气（只发城市名，不发聊天内容、

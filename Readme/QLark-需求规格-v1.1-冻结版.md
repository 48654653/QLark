## v1.1 → v1.2 变更摘要（M2 开工时发现的架构缺口）

**问题**：v1.1 §1.2 只写了「NapCat → OneBot 11 HTTP 服务端 127.0.0.1:3000」。
但 OneBot 的 **HTTP 服务端模式是单工的**——只能业务程序主动 POST 到 NapCat 发动作，
NapCat **不会**把消息推给我们（技术文档 §3.2 明确写了"事件上报才走 HTTP 客户端模式"）。

**只按 v1.1 实现，结果是"登录成功、仪表盘在线，但机器人永远不回复"。**

| # | 项 | v1.1 | v1.2 |
|---|---|---|---|
| 1 | 事件通道 | 未定义（隐含"用 HTTP 服务端"） | **新增 EventServer**（默认 `127.0.0.1:3001`），向 `onebot11_<QQ>.json` 写入 `httpClients` 条目让 NapCat 主动推送事件 |
| 2 | 网络配置 | 只写 `httpServers` | **同时写 `httpServers`（动作）+ `httpClients`（事件）**；两者缺一即判为"未配好"，自动补写并重启一次 |
| 3 | 端口自检 | 检查 3000 / 6099 | 增加 **3001（事件通道）** |
| 4 | 仪表盘 | 6 项 | 增补运行信息两行：**消息处理**（已回复/收到/丢弃/排队）、**事件服务**（监听中 · host:port） |
| 5 | 机器人开关 | 未定义 | 新增**暂停回复**总开关（仪表盘「运行信息」面板） |

其余规格（人设、记忆、权限、图片链路）不变。

| 8 | 指令是否计费/入记忆 | 未定义 | **不入记忆、不调用模型**、不计 Token；但仍计入今日消息收发 |

## 1. 产品定位与硬约束

QLark（云雀）是一款基于 **NapCat** 框架的 QQ 聊天机器人 **Windows 桌面客户端**，适配 **OpenAI API 格式**的 Key 调用。主打**多人设对话**与**记忆功能**，支持群聊与私聊。双击图标即用，无黑窗，前台控制页功能多而不乱。

| # | 硬约束 | 落地要求 |
|---|---|---|
| 1 | 双击即开 | 依赖 `-q` 快速登录（免扫码）+ 内置 NapCat 运行时 + 内置 VC++/DLL |
| 2 | 配置全在 GUI 完成 | 用户不接触 JSON、不开浏览器、不进 WebUI |
| 3 | 无黑窗 | `CREATE_NO_WINDOW`；且必须**持续读 stdout**（否则卡死 NapCat） |
| 4 | 界面现代美观 | 不用 Tkinter；深色默认 + 浅色可切；字体优先微软雅黑 |
| 5 | 登录按钮常驻 | 右上角，模态面板，不随模块切换消失 |

## 2. 技术基线（已验证，不再重复验证）

| 结论 | 出处 |
|---|---|
| NapCat 启动命令本质是 `node.exe ./index.js`，工作目录必须是 `runtime/napcat/` | 技术文档步骤 5 |
| 快速登录：`-q <QQ号>` 或 `NAPCAT_QUICK_ACCOUNT`，凭据在 `%USERPROFILE%\Documents\Tencent Files\<QQ号>\` | §8.2 |
| **协议端默认不开任何端口**，必须写 `onebot11_<QQ号>.json` 并**重启**才生效 | §3.3、步骤 7 |
| **配置文件不支持热重载** | 坑 7、§8.1 |
| WebUI 内部 API 是 HMAC 动态密钥，静态 token 调不通 → **直接读写配置文件** | 坑 8、§9.1 |
| 杀进程必须杀**父进程树**；只杀 worker 会被自愈机制重拉 | 坑 10 |
| `cache/qrcode.png` 登录成功后**不删除**；**每约 121 秒覆盖重写** | 坑 21、坑 22 |
| 启动输出未被持续读取 → 管道缓冲写满 → **进程阻塞** | 坑 23 |
| 图片 URL **约 2 小时过期** | 坑 17 |
| NapCat 无数据库，消息 LRU 约 5000 条过期；消息 ID 非连续 | 坑 14、坑 16 |
| `get_status` 返回 `{"online":true}` 作为链路判据 | 步骤 8 |

## 3. 页面规格

### 3.1 全局

- 主题：**黑夜（默认）/ 白天**，选择持久化
- 字体：UI 用**微软雅黑**；日志区用**等宽字体**（Consolas / Cascadia Mono）
- 右上角常驻**登录按钮**，模态面板，不随模块切换消失
- 高 DPI 适配（125% / 150%）
- **二维码必须保持白底黑块**——黑夜模式禁止反色或加滤镜

### 3.2 登录面板（模态）

状态机显示当前阶段：

```
[环境自检] → [已保存账号? ]
   ├ 有 → 快速登录中 → 成功 → [初始化网络] → [重启 NapCat] → [就绪]
   │                 └ 失败 → 降级扫码
   └ 无 → 扫码
[扫码中]：显示 qrcode.png，每约 121s 自动刷新
[已登录]：显示 QQ 号 + 昵称 + 在线状态 +「退出登录」+「切换账号」
```

### 3.3 仪表盘（6 项）

| 元素 | 说明 |
|---|---|
| 今日 Token 消耗量 | 持久化，本地时区 00:00 重置 |
| 今日调用次数 | LLM 调用次数（含总结调用） |
| 连接状态 | **仅 QQ/NapCat 链路**（`get_status` + 3000 端口） |
| 当前登录 QQ 号 | 未登录显示"未登录" |
| 今日消息收发条数 | 收 / 发分开 |
| 活跃会话数 | 群 / 好友 |

### 3.4 模型配置

| 元素 | 说明 |
|---|---|
| API Key | 安全存储（DPAPI 或限制 ACL） |
| Base URL | 归一化：自动补 `/v1/chat/completions` |
| 模型名 | **自由文本输入**，不能写死下拉 |
| 最大输出 Token | 校验范围 |
| 温度 | 校验范围（部分推理模型不接受 temperature） |
| **应用** | 立即生效，无需重启软件 |
| **测试** | L2：`POST /chat/completions`，`max_tokens=1`，prompt=`"1"`（约 6 token）→ 成功提示"连接正常"；失败按 `401 / 404 / 429 / 超时 / TLS` 分类回显 |
| 多模型槽位 | 对话模型 / 视觉模型 / 总结模型（可各自不同 Key） |

> ⚠ 涉及 NapCat 侧的配置（OneBot 端口、token、日志开关）另设区块，标注 `⚠ 需重启 NapCat` +「立即重启」按钮。

### 3.5 人设配置

- 布局：**可滚动的人设列表 + 新建/删除按钮**（不再是固定 9 标签）
- 默认存在：人设1、人设2、人设3
- **人设1 不可删除**（出厂默认、新会话初始使用）
- 上限 **99** 个
- 字段：名称 / 头像 / 系统提示词（多行）/ 启用 / 可选覆盖（模型、温度、最大 Token）
- 删除人设：GUI 二次确认 → 使用该人设的群/用户**静默切回人设1（无提示）** → **该人设全部记忆一并删除**
- 空人设：不发送 system 消息（不是发空字符串）
- **权限区**：`☑ 仅白名单可切换人设`（默认勾选）+ 白名单 QQ 列表（增删）

### 3.6 记忆面板

| 元素 | 说明 |
|---|---|
| 记忆轮数 W | 数字输入框，默认 **20**，可改 |
| 自动总结 | checkbox，默认**开启**；开启时压缩触发轮数 S ≡ W |
| 记忆浏览 / 编辑 / 删除 | 按会话分组查看原文与当前总结，支持删除（用户必然会想改） |
| 容量提示 | 会话数、已压缩次数、占用体积 |

### 3.7 日志输出

- 来源分开：**QLark 自身日志** / **NapCat 原始输出**
- 独立读线程 + 环形缓冲（不做会卡死 NapCat）
- 级别过滤 / 关键字搜索 / 暂停自动滚动 / 清空 / 导出

- 二维码字符画折叠或过滤，避免污染日志
- `napcat.json` 的 `fileLog` 开关暴露到 GUI

## 4. 消息处理规格

### 4.1 触发规则

| 场景 | 规则 |
|---|---|
| 群聊 | **严格只认 @**（`at` 段 `user_id` == 机器人）。回复机器人消息但未 @ → **不触发**。@全体成员不算。纯文本 "@昵称" 不算 |
| 私聊 | 全部触发（含非好友、临时会话） |
| 指令 | 群聊 `@机器人 /person N`；私聊直接 `/person N` |

### 4.2 忽略与过滤

- 自己发的消息
- 其他机器人
- 系统消息 / 撤回事件
- 黑名单 QQ / 群
- 重复事件（msg_id 去重）
- 总开关"暂停回复"

### 4.3 消息段 → 占位文本降级映射表

> ⚠ 因 `messagePostFormat: "array"`，语音到达时是 `{"type":"record",...}` 段，**不是** `[语音消息]` 文本。占位文本必须由 QLark 自己生成。

| 段类型 | 处理 |
|---|---|
| `text` | 取原文 |
| `at` | 触发用的 @ 不计入正文；其他 @ → `@昵称` |
| `image` | 走视觉链路；记忆库中存 `[图片]` 占位 |
| `record` | `[语音消息]`（不做 ASR） |
| `video` | `[视频]` |
| `file` | `[文件：<文件名>]` |
| `face` / `mface` / `bface` | `[表情]` |
| `json` / `xml` | `[卡片消息]` |
| `forward` | `[合并转发]` |
| `reply` | 不占正文 |
| 未知 | `[不支持的消息类型]` |

### 4.4 处理流水线

```
事件到达
  → 去重（msg_id）
  → 过滤（自己 / 其他机器人 / 系统 / 黑名单 / 总开关）
  → 触发判定（群聊 at 段含机器人 user_id）
  → 指令分支（/person 等）—— 不写记忆
  → 入队（按 session_id 串行；全局并发上限 N）
  → 图片处理（立即下载 → 长边≤1024 + JPEG → base64）
  → 装配上下文（人设 + 总结 + 最近 W 轮 + 本轮）
  → 调用模型（超时 / 重试 / 失败提示）
  → 回复（长文本分段或合并转发；可选引用原消息）
  → 落库（原文 + 统计）
  → 检查是否触发压缩
```

### 4.5 指令集

| 指令 | 说明 |
|---|---|
| `/person N` | 切换人设，回执"已切换为人设 N：<名称>" |
| `/help` | 指令列表 |
| `/reset` | 清空本会话（当前人设）记忆，二次确认 |
| `/memory` | 查看当前总结 |
| `/status` | 当前人设 / 会话键 / 记忆轮数 |

> 全角 `／` 兼容；非法参数（`/person 999`）返回提示；切换指令不写记忆。

## 5. 人设模型规格

### 5.1 身份与编号

| 概念 | 说明 |
|---|---|
| `persona.uid` | **内部不可变 ID**，自增，永不复用。**记忆全部用它绑定** |
| 界面编号 | 列表位置，`1..N` 连续，删除后重排 |
| `/person N` | N = **界面编号**，运行时映射到 uid |

> 重排不会导致记忆错配，因为记忆按 uid 绑定；且人设删除时其记忆已一并删除。

### 5.2 作用域（会话独立）

| 会话 | 当前人设存放 |
|---|---|
| 群 | `session_id = group:<群号>` 一行 |
| 私聊 | `session_id = private:<QQ号>` 一行 |

新会话初始人设 = **人设1**（uid 最小且不可删的那个）。

### 5.3 切换权限

| 场景 | 默认 | 可调 |
|---|---|---|
| 群聊 `/person` | **仅白名单 QQ** | 关闭开关 → 所有人可切 |
| 私聊 `/person` | **允许本人自由切** | — |
| GUI 编辑人设 | 管理员（本机使用者） | — |

白名单：**全局一份** QQ 列表，GUI 维护。

### 5.4 删除人设的处理

```
1. GUI 二次确认（"将同时删除该人设的全部记忆，不可恢复"）
2. 所有 active_persona == 该 uid 的会话 → 静默改为 人设1 的 uid【无提示】
3. 删除该 uid 的全部记忆（messages / summaries）
4. 从 personas 表删除；界面编号重排
```

## 6. 记忆模型规格

### 6.1 键设计

```
session_id  = group:<群号>        |  private:<QQ号>
memory_key  = <session_id>:p<persona_uid>
```

效果：

| 需求 | 实现 |
|---|---|
| 群聊内所有人共用一套记忆 | 同一 `group:<群号>` 下所有成员共享 |
| 不同人设记忆不互通 | memory_key 带 `p<uid>` |
| 不同群不干扰 | session_id 带群号 |
| 私聊按用户隔离 | session_id 带 QQ 号 |

### 6.2 记忆参数

| 参数 | 默认 | 说明 |
|---|---|---|
| 记忆轮数 W | **20** | 每次请求携带的最近原文轮数 |
| 自动总结 | **开启** | 关闭则不压缩，原文无限累积（受容量上限约束） |
| 压缩触发轮数 S | **≡ W** | 未压缩原文累积满 W 轮触发。无独立设置项 |
| 摘要字数上限 | 300 | 提示词约束 + 超长截断兜底 |

### 6.3 压缩算法（冻结）

```
每完成一次成功问答（写入 user + assistant 两条）后：
    rounds = 该 memory_key 下「未压缩」的完整轮数

    if 自动总结开启 and rounds >= W:
        material = [老总结(若有)] + [最早的 W 轮原文]
        new = LLM(总结模型, material, "压缩到 300 字以内，保留事实与用户偏好")

        if new 失败:
            标记 pending；【不删除任何原文】；下一轮重试
            return

        事务 {
            summaries[memory_key] ← new     # 老总结块被顶掉，信息已合并在 new 内
            这 W 轮原文标记 summarized = 1
        }
```

**组装请求时的上下文**

```
[system]  人设提示词                       ← 为空则整条不发
[system]  [长期记忆] <当前总结>             ← 独立记忆块，不占轮次
...最近 W 轮原文...
[user]    本轮消息（含 image_url 段）
```

- 若 token 估算超预算 → 从**最早的原文**开始丢弃，**总结始终保留**
- 摘要中若包含图片 → 以 `[图片]` 占位，绝不把 base64 写入记忆

### 6.4 摘要的递归性质

采用**合并式**：`新总结 = 总结(老总结 + 新 W 轮)`。老总结块被替换，但其信息已并入新总结 → 记忆视野**无限延伸**，代价是随时间衰减。

### 6.5 图片链路

```
收到 image 段
  → 【立即下载】（URL 约 2 小时过期）：超时保护 + 大小上限
  → 预处理：等比缩放到长边 ≤ 1024，转 JPEG（base64 膨胀 33%）
  → 转 data URL 交给视觉模型
  → 记忆库中只存 [图片]
```

- 多图消息：全部处理，但设张数上限
- 动图 / 表情包（gif / webp）：取首帧或跳过
- **模型不支持视觉时降级**：提示用户或改走独立视觉模型槽位

## 7. 数据模型（SQLite，WAL）

路径：`%LOCALAPPDATA%\QLark\data\qlark.db`

```sql
-- 人设
CREATE TABLE personas (
  uid            INTEGER PRIMARY KEY AUTOINCREMENT,  -- 不可变，永不复用
  slot           INTEGER NOT NULL,                   -- 界面编号 1..N（可重排）
  name           TEXT    NOT NULL DEFAULT '',
  avatar_path    TEXT    DEFAULT '',
  system_prompt  TEXT    DEFAULT '',
  enabled        INTEGER DEFAULT 0,
  model_override       TEXT    DEFAULT NULL,
  temperature_override REAL    DEFAULT NULL,
  max_tokens_override  INTEGER DEFAULT NULL,
  created_at     INTEGER NOT NULL
);

-- 会话状态（每群 / 每私聊用户一行）
CREATE TABLE session_state (
  session_id     TEXT PRIMARY KEY,        -- group:<群号> | private:<QQ号>
  session_type   TEXT NOT NULL,           -- group | private
  session_ref    TEXT NOT NULL,           -- 群号 | QQ号
  active_persona INTEGER NOT NULL,        -- personas.uid
  updated_at     INTEGER NOT NULL
);

-- 记忆：对话原文（只存触发了机器人的问答）
CREATE TABLE messages (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  memory_key  TEXT    NOT NULL,           -- <session_id>:p<persona_uid>
  role        TEXT    NOT NULL,           -- user | assistant
  content     TEXT    NOT NULL,           -- 图片以 [图片] 占位
  has_image   INTEGER DEFAULT 0,
  tokens      INTEGER DEFAULT 0,
  msg_id      TEXT,                       -- 用于去重
  created_at  INTEGER NOT NULL,
  summarized  INTEGER DEFAULT 0
);
CREATE INDEX idx_msg_key ON messages(memory_key, summarized, id);

-- 记忆：当前总结（一个 memory_key 最多一条）
CREATE TABLE summaries (
  memory_key  TEXT PRIMARY KEY,
  content     TEXT NOT NULL,
  covered_to  INTEGER NOT NULL,           -- 已覆盖到的 messages.id
  pending     INTEGER DEFAULT 0,          -- 压缩失败待重试
  updated_at  INTEGER NOT NULL
);

-- 每日统计
CREATE TABLE stats_daily (
  date              TEXT NOT NULL,        -- 本地时区 YYYY-MM-DD，00:00 重置
  prompt_tokens     INTEGER DEFAULT 0,
  completion_tokens INTEGER DEFAULT 0,
  calls             INTEGER DEFAULT 0,
  errors            INTEGER DEFAULT 0,
  msg_in            INTEGER DEFAULT 0,
  msg_out           INTEGER DEFAULT 0,
  PRIMARY KEY (date)
);

-- 全局配置（含 model / base_url / api_key(加密) / W / 自动总结 / 权限开关 / QQ号 / 白名单）
CREATE TABLE config (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

-- 人设切换白名单
CREATE TABLE persona_whitelist (
  qq TEXT PRIMARY KEY
);

-- 会话活跃度（用于"活跃会话数"）
CREATE TABLE session_activity (
  session_id   TEXT PRIMARY KEY,
  last_active  INTEGER NOT NULL,
  msg_count    INTEGER DEFAULT 0
);
```

## 8. 关键流程

### 8.1 启动与登录状态机

```
[启动]
  ├─ 单实例锁（已有实例 → 激活已有窗口并退出）
  ├─ 环境自检：VC++ 运行库 / crypto.dll / ssl.dll / 端口可用性 / WebView2 运行时
  │     └─ 缺失 → 自动补齐（VC++ 静默装；DLL 从内置副本拷）
  ├─ 清理孤儿 node.exe（上次崩溃残留，否则占住 3000/6099）
  ├─ 读取本地保存的 QQ 号
  │     ├─ 有 → 删除 cache/qrcode.png → spawn(node.exe, ./index.js, -q <QQ号>)
  │     │        ├─ 日志「正在快速登录」+「Worker进程已登录成功」→ 登录成功
  │     │        └─ 日志「将使用二维码登录方式」→ 降级扫码
  │     └─ 无 → 扫码分支
  ├─ 扫码分支
  │     ├─ spawn(node.exe, ./index.js)     # 不带 -q
  │     ├─ 轮询 qrcode.png：出现 且 mtime > 进程启动时间 → 显示
  │     │                    mtime 变化（约 121s）→ 刷新
  │     └─ 登录成功 → 隐藏二维码 → 保存 QQ 号
  ├─ 初始化网络
  │     └─ 检查 onebot11_<QQ号>.json 的 network 段
  │           ├─ 已启用 → 跳过
  │           └─ 未配置 → 备份 + JSON 合并写入 → 杀父进程树重启 NapCat
  ├─ 轮询 127.0.0.1:3000 就绪 → get_status 验证 → 仪表盘绿灯
  └─ [就绪] 开始消费消息
```

### 8.2 停止

```
直接终止进程树（taskkill /PID <父PID> /T /F），无需优雅等待
```

### 8.3 进程管理要点

| 要点 | 做法 |
|---|---|
| 无黑窗 | `subprocess.Popen(..., creationflags=CREATE_NO_WINDOW)` |
| 不阻塞 | 独立线程持续读 stdout → 环形缓冲 + 日志文件 |
| 工作目录 | `runtime/napcat/` |
| 停止 | 杀**父进程树** |
| 孤儿清理 | 启动时检查并清理上次残留的 node.exe |
| 崩溃恢复 | 自动重启 + 最大重启次数 |

## 9. 非功能需求

### 9.1 稳定性

- 单实例锁
- 孤儿进程清理
- NapCat 崩溃自动重启（限次数）+ 断线重连
- 端口占用检测与自动改端口
- 记忆写库失败不阻塞回复

### 9.2 安全与隐私

- API Key 用 Windows DPAPI 加密后落库（至少限制文件 ACL）
- 代理配置：模型请求可走代理，**NapCat / QQ 不走代理**
- 隐私提示：群聊文字与图片会发送给第三方 API，且本地落盘
- 记忆查看 / 删除入口（用户可自清）

### 9.3 合规与风控

- 首启明确告知：QQ 机器人存在**风控 / 封号风险**
- 发送速率限制
- 超长 / 频繁消息抑制
- 可选敏感词过滤

### 9.4 打包分发

- PyInstaller / Nuitka，`--noconsole`
- 内置 NapCat 运行时（约 300MB+）+ 两个 DLL + `vc_redist.x64.exe`
- 内置 DLL 可能被杀软误报 → 首启与文档说明
- 程序目录（可能只读）与用户数据目录（`%LOCALAPPDATA%\QLark\`）分离
- 首启向导：模型配置 → 登录 → 人设 → 记忆

## 10. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.13 | 需求指定 |
| GUI | **pywebview**（WebView2） | HTML/CSS 做深色主题最省力；二维码直接 `<img>`；日志虚拟滚动 |
| 后端 | Python + `threading` / `queue` | 进程管理与读线程 |
| 存储 | **SQLite（WAL）** | 并发写安全、断电安全、单文件 |
| HTTP | `httpx` / `requests` | 调 OpenAI 兼容 API |
| 与 NapCat | **OneBot 11 HTTP 服务端** `127.0.0.1:3000` + Bearer token | 技术文档已验证 |

> **pywebview 的代价（已接受）**：依赖 Edge WebView2 Runtime（首启自检，缺失则引导安装）；打包体积约 150MB；需编写前端 HTML/CSS/JS。
